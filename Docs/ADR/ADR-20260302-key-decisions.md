# ADR: Баланс качества multi-turn и ускорение первого токена

## Контекст
После перехода OpenAI в backend появились два приоритета:
1) снизить TTFB, особенно на первом запросе после старта;
2) вернуть релевантность multi-turn без возврата к полной истории и без роста latency.
Дополнительно в ходе отладки возник шум логов по shortcut-системе.

## Решения
1. Для OpenAI `/v1/responses` использовать контекст: последние 3 сообщения `user` + последнее `assistant` (0/1), с маппингом типов:
   `user -> input_text`, `assistant -> output_text`.
2. Перейти на shared `reqwest::Client` в Tauri state (pooling/keep-alive) и добавить one-shot warm-up в фоне на старте приложения.
3. Временно заглушить shortcut-логи через локальный макрос `shortcut_log!` до завершения проверки стабильности hotkeys.

## Альтернативы (кратко)
- Передавать полную историю (включая весь assistant): отклонено из-за деградации latency и роста стоимости.
- Создавать `reqwest::Client::new()` на каждый запрос: отклонено из-за потери reuse соединений.
- Полностью удалить shortcut-логи: отклонено, выбран временный mute с возможностью быстро вернуть вывод.

## Последствия
- Улучшена связность второго/третьего хода без возврата к тяжёлому контексту.
- Снижено время до первого чанка за счёт connection pooling и warm-up (в пределах сетевых условий).
- Текущая диагностика shortcut-проблем в рантайме ограничена, нужен контролируемый возврат логов.
